# 지속 제작 기반 구현·검증 · 2026-10-18

기존 게임/하네스를 유지하고 `.autodev/director.py`를 추가했다. 상위 관리자 한 개가 의존성 큐의 다음 제작 묶음을 골라 기존 goal/plan/run을 호출한다. 작성 후 필수 QA, 별도 read-only 편집 검토, 제한 수정, 검증된 통합/개발 브랜치 백업을 거쳐 다음 묶음으로 진행한다. 구현 완료와 전체 게임/출시 후보 완료는 구분한다.

제작 기준 문서 9개를 확정했다. 1998년의 인쇄소, 백인호/윤해린/0번 의뢰인, 3장 18개를 출발 목표로 하되 기존 8개 해답과 v1 저장을 보존한다. 60~90분, 재미, 학습, 미적 완성도, 청취는 사람의 관찰 전까지 미검증이다. 새 데이터·원본 자산·캠페인 셸은 정확한 파일 허용 목록으로만 추가한다. 모델은 이 목록이나 신뢰된 테스트를 수정할 수 없다.

검증된 기반:

- Windows/공통 인프라 70개: 69 통과, 심볼릭 링크 권한이 없는 환경 검사 1개 스킵. 신규 디렉터 검사 16개를 포함한다.
- Linux 전용 기존 CLI/WSL fixture 3개: 설치된 Ubuntu의 Python에서 3개 통과. Windows에서 처음 실행한 해당 fixture 2개는 환경 오류를 냈으며 기록을 보존하고 테스트 자체는 수정하지 않았다.
- 새 Godot 전용 프로브 6개: 검증된 별도 엔진의 구문 검사 통과. 기능이 아직 없는 단계의 구문 검사이며 캠페인 기능 통과라는 뜻은 아니다.
- 실제 별도 프로세스의 OS 잠금 충돌/해제, 단계 의존성, 중단 뒤 재개 대상 선택, 인증/사용량 실패 시 추가 모델 호출 차단, 독립 작업 진행, 검토 누락/오래된 스냅샷의 통합 차단, 새 메타데이터 정확한 범위, 영구 파일 오류의 원본/임시 증거 보존을 검사했다.
- 첫 fault injection에서 새 `.uid` 메타데이터 이력의 `before[rel]` 접근이 KeyError를 냈다. 없는 이전 값은 null로 기록하도록 구현을 고쳤으며 같은 검사를 유지해 통과했다.
- 이전 스프린트의 상태 JSON 교체 오류를 바탕으로 Windows 공유 오류에 한해 원자적 교체를 최대 2초 동안 재시도한다. 실패 시 임시 파일과 원본을 보존한다. 게임/오디오의 대기 시간을 늘려 성공 처리하는 변경은 아니다.

독립 실행 환경은 기존 프로젝트 Python/네이티브 Codex/패치 엔진과 템플릿을 재사용한다. 새 시스템 설치, 관리자 권한, 인증 복사, 유료 서비스, 예약 작업/레지스트리 등록은 하지 않는다. OS 잠금/PID가 없으면 백그라운드 실행 중이라고 표시하지 않는다. PC 자동 종료는 구현하지 않았다.

첫 실제 제작 E2E는 S02의 의뢰서와 기록함이다. 이 문서의 기반 커밋 시점에는 **게임 E2E 및 출시 후보는 아직 미완료**이며, 실행 후의 진짜 상태/QA/커밋/빌드는 생산 작업 환경 `.autodev/state/production/report.json`, `현황_KO.txt`, `.autodev/runs/`가 기준이다. 후속 큐는 캠페인 셸→신규 퍼즐/서사 결말→원본 아트/음향→제품 검토→출시 후보 검증으로 이어진다. 새 제품 기본 장면과 정확한 Windows 빌드까지 검사해야 출시 후보를 표시할 수 있다.

사용법은 [GAME_PRODUCTION_KO.md](GAME_PRODUCTION_KO.md)를 참조한다. 실행·중복 차단·pause/resume의 실제 게임 증거는 별도 실행 로그에 누적한다. 인프라 mock 검사만으로 실제 게임 제작 또는 장기 실행의 성공을 주장하지 않는다.
