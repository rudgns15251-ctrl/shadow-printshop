# 하네스 v0.7-D — 격리 장애 시나리오 검증

## 목적

v0.7-A 사전 진단, v0.7-B 명시적 복구, v0.7-C 중단 및 연속 실행 제어를 **실패 상황에서도 안전하게 유지하는지** 테스트합니다.

**실제 Codex, WSL, Godot를 실행하거나 기존 게임 코드·Git 이력·SQLite DB를 수정하지 않습니다.**
테스트는 모의 응답·임시 폴더·임시 SQLite DB에서 수행합니다. 아래 모든 시나리오의
통과는 프로그램의 동작을 검증하는 것이며 사용자 PC의 실제 장애/권한/전원 장애를 재현한 결과는 아닙니다.

## 테스트 범위

1. WSL/인증 관련 FAIL·WARN 감지 시 실개발 진입 거부
2. 검사 항목 누락 시 진입 거부
3. 손상된 SQLite 파일 탐지 및 원본 바이트 보존
4. 중복 작업 잠금 거부
5. 오래된 중단 요청이 새 실행에 적용되지 않도록 방지
6. 타임아웃, 코드 오류, 범위 위반, Godot QA 실패를 자동 복구에서 제외
7. triage 및 recover --check가 변경을 수행하지 않음
8. 승인 불가능한 상태에서 recover --apply 거부
9. 실행 보고서의 중복 기록 방지 및 최소 정보 기록
10. Codex 비정상 종료 및 타임아웃 시 blocked 상태·작업 공간 보존
11. Godot QA / 독립 QA 실패 시 검증 성공 처리 금지
12. 메인 Git 불결·running 작업 잔존·중단 요청 시 중복 작업 거부
13. 자동 재시도 기본값 0 확인

## 설치 후 실행

PowerShell, 프로젝트 루트:

```powershell
.\.venv\Scripts\python.exe v07d_fault_audit.py --check
.\.venv\Scripts\python.exe v07d_fault_audit.py --full --report
```

단독 검사는 새 장애 주입 테스트 18개를 실행합니다. 전체 검사는 기존 테스트까지 실행합니다.
성공해야 할 테스트 수는 설치된 테스트의 버전에 따라 달라집니다. 정상 종료 코드와 OK를 확인하세요.
`--report`로 생성한 JSON은 `.data/v07d-reports/`에 저장합니다.

## 한계 및 후속 확인

- 회귀 테스트는 네트워크 장애, 실제 전원 차단, Windows/WSL 파일 잠금 경합을 직접 재현하지 않습니다.
- `harness.py run --live`를 직접 실행하면 `autopilot.py`의 사전 진단 관문을 거치지 않는 기존 설계입니다.
- 전체 자동 개발 안정성은 새로운 게임 작업을 등록한 후 실제 코드 작성·Godot QA·수동 승인 절차로 확인해야 합니다.
- `PLAN-001`의 `review` 상태는 별도 승인이 필요한 기존 작업으로서 변경하지 않습니다.
