# Harness v0.5: 자동 수정 및 하네스 소유 QA

- `PROTO-001`이 수동 플레이 7개 항목을 통과했다면 사용자가 별도로 승인한 뒤 진행한다.
- `PROTO-002`는 v0.5 작업이며, 기존 Godot 프로젝트에 **회귀 테스트와 시나리오 문서만 보강**한다.
- 검증 단계는 기존 경로·파일 검사 → Godot import/smoke/launch → **하네스 소유 외부 씬 입력 스모크 검사** 순서다.
- 외부 검사 스크립트는 하네스 루트의 `qa/scene_probe.gd`에 있으며, 게임 소스와 별도다. 실행할 때 임시 디렉터리에 복사하여 테스트하므로 Codex의 작업 트리를 수정하지 않는다.
- 자동 수정을 시도하는 경우는 **Codex CLI가 정상 종료했고, 출력 파일이 허용 경로 안에 있으며, 검증 실패가 복구 가능한 경우**뿐이다. 최대 2회 추가 시도한다. 어떤 단계든 에이전트가 허용 경로를 벗어난 파일을 변경하거나, Git 커밋·심볼릭 링크를 만들면 자동 재시도 없이 중단한다.
- Codex가 만든 smoke/regression 테스트는 여전히 자기 검증이며 독립적인 오류 탐지를 보장하지 않는다. 하네스 QA probe도 **씬 로드·입력 이벤트 전달 중 크래시가 없고 변화 여부를 진단**할 뿐 퍼즐의 정답·재미를 보장하지 않는다.
- 실제 Godot 실행은 설치된 사용자 OS의 권한으로 이뤄지며 완전한 보안 샌드박스가 아니다. 가능하면 별도 표준 권한 VM에서 실행한다.
- 작업 성공 후 자동 승인·Git 병합은 하지 않는다. 사용자는 실제 게임을 재플레이하고 작업 결과를 승인한다.

## 진행 순서

1. `python harness.py approve PROTO-001` (기존 검증 결과 확인 후)
2. v0.5 압축 파일을 하네스 루트에 풀고 `python install_v05.py` 실행.
3. `python autopilot.py plan`에서 `PROTO-002 pending READY` 확인.
4. `python autopilot.py run --live --max-tasks 1 --minutes 45`로 신규 작업 시작.
5. `PROTO-002 review`라면 독립 QA 보고서 `logs/qa/PROTO-002.json`을 읽고 직접 플레이 후 승인.
