# SELECT-001 — C01 실험 적합성 및 기존 결과 정합성 감사

감사일: 2026-10-12. 대상: 현재 작업공간의 C01 실험 프로토타입과 기획·조사·평가 기록.

**판정: C01을 우선 7일 실험의 출발점으로 유지하되, 실험 완료·독립 만족도·상품성·최종 게임 선정은 미검증이다. 최종 결정은 PENDING_HUMAN_APPROVAL이다.** 새 게임을 확정하거나 기존 결과를 승인하는 문서가 아니다. 현재 두 퍼즐을 보존한 제한된 실험으로 기술 정확성, 풀이 다양성, 시청각 경험과 제작 시간을 확인할 수 있다는 판단도 실험 적합성 가설이다. 이번 작업은 이 문서만 작성하며 코드·게임 자산·테스트·승인 기준·Git 기록을 변경하지 않는다.

## 1. 감사 입력과 증거의 경계

- [PLAN-002](../design/independent_concepts.md): 독립 신규 콘셉트 10개, 그중 C01·C04·C08의 실험·제품 가설.
- [RESEARCH-001 보고서](../research/steam_market_report.md)와 [경쟁작 JSON](../research/steam_competitors.json): 기존 공식 상점 텍스트 관찰, 링크와 공백.
- [ASSESS-001](../research/market_assessment.md): 상품성 보류, 잠정 C01 실험 순서, 반증·중단 기준.
- 현재 `game/project.godot`, `main.tscn`, `scripts/game_state.gd`, `main.gd`, `board_view.gd`, `tests/smoke_test.gd`, `regression_test.gd`, `progress_clarity_test.gd` 및 `docs/iter_002_focus_observer.gd`.
- [PROTO 기록](../game/docs/PROTOTYPE_NOTES.md), [VALIDATION.json](../game/docs/VALIDATION.json), [회귀 QA](../game/docs/QA_REGRESSION.md), [ITER-001](../game/docs/ITER-001_NOTES.md), [ITER-002](../game/docs/ITER-002_NOTES.md). 저장소의 `tasks/backlog.json`, `engine_adapter.py`, `qa_gate.py`, `qa/scene_probe.gd`도 검증 범위 확인에 사용했다.

‘구현’은 현재 소스에 기능이 있다는 뜻이며 실행 성공과 다르다. ‘기존 자동 검증’은 이전 문서의 기록으로, 이번에 재실행한 결과와 구분한다. 사람 검증은 사용자 보고와 신규 독립 관찰을 분리한다. 외부 시장 사실은 기존 자료에 기록된 범위만 인용하며 새 웹 조사·현재 상점 상태 재확인은 수행하지 않았다. 이전 개인 맥락이나 다른 프로젝트를 사용하지 않았다.

기존 조사 기록에 따르면 **XOR 명암 반전과 목표 모양 맞추기는 [VOI](https://store.steampowered.com/app/545690/)에도 존재한다.** 반복 인쇄·제한 판 회전·취소·최소 수 조합의 차이는 가설이며 VOI에 나머지 기능이 없다는 근거는 없다. [Zerko](https://store.steampowered.com/app/2862990/)는 숫자 목표 역산의 부분 비교, [.projekt](https://store.steampowered.com/app/759000/)는 실루엣 추론의 인접 비교다. 둘을 동일 XOR 퍼즐로 단정하지 않는다. 이 링크들은 RESEARCH의 출처를 재인용한 것이며 이번 감사에서 열람하지 않았다.

C04의 공연 운영·장비/홍보 배분, C08의 방향 부표·기록 비교에도 기존 문법 중복이 기록되어 있다. 노선/피로의 교환이나 자기 고스트의 경험 차이는 미확인이다. 따라서 C01만 특별히 독창적이라는 결론은 없다. 동일 조건 가격, 최근 리뷰 본문, 실제 플레이·구매 가치 반응, 판매량·매출은 세 후보 모두 부족하다. .projekt의 60/120퍼즐 충돌과 가격의 지역·통화·캐시 시점 혼재도 미해소다. 리뷰를 판매량으로 환산하거나 확률·점수로 공백을 채우지 않는다.

## 3. 기능 구현 — 현재 소스에서 확인한 것

| 기능 | 현재 구현과 제한 |
| --- | --- |
| 상태 규칙 | `game_state.gd`는 UI와 분리된 RefCounted. 0/1 배열, 도장 A(꺾임)/B(막대), 90도 회전 정규화, XOR 인쇄, 보드 일치 판정이 있다. |

고정 마스크 XOR는 최종 보드에서 순서 교환과 동일 마스크 두 번 상쇄가 성립한다. 다만 현재 구현은 중간에 해결되면 추가 인쇄를 거부하므로 실제 요청열의 수락 여부까지 자유 교환된다고 주장하지 않는다. 새 퍼즐은 단순 회전·표면 장식만 다른 반복인지, 선택·회전의 추론이 다른지 따로 검수해야 한다. 교환성 자체가 재미 실패 증거는 아니다.

현재 PATH에서 `godot`, `godot4`, `godot.exe`, `Godot.exe`를 찾지 못했고 `GODOT_BIN`은 미설정, `.data/godot_path.txt`는 없다. 이번 감사의 Godot 테스트·파싱·독립 QA·GUI 실행은 **미실행**이다. 외부 경로를 탐색하거나 엔진을 설치하지 않았다. 엔진 부재는 테스트 통과도 게임 결함 판정도 아니다.

엔진이 준비된 후 기존 smoke/regression과 추가 progress 검사는 각각 종료 코드 0·해당 성공 표식·파싱/스크립트 오류 없음으로 확인해야 한다. 독립 scene probe와 실제 Windows 입력/화면 관찰은 별도다. 보호 테스트나 승인 기준을 낮추지 않는다.

## 5. 사람 검증 — 보고와 독립 만족도 구분

[회귀 QA 문서](../game/docs/QA_REGRESSION.md)와 PROTO-002 manifest에는 사용자가 도장 선택·회전·인쇄·취소·초기화·해결·다음 퍼즐 이동의 작동을 확인했다고 기록되어 있다. 이는 **기존 사용자 기능 확인 보고**다. 원본 관찰 세션·빌드/엔진 버전·입력별 로그는 이 감사에서 확보하지 않았고, 현재 코드 전체를 새로 검증한 결과로 확대하지 않는다.

PROTO-001의 `human_playtest: NOT PERFORMED`는 작성 당시 기록이며 이후 사용자 보고와 시간 범위가 다르다. ITER 문서의 새 사람 플레이테스트 미실시와도 모순이 아니다. 신규 플레이어의 독립 규칙 이해·풀이 만족·자발적 지속·난이도·구매 가치는 여전히 미검증이다. 감사 에이전트는 실제 게임을 플레이하거나 화면·사운드를 평가하지 않았다.

7일 실험은 원문 진단 기준을 그대로 유지한다: 처음 접하는 성인 **8명** 목표, **6명 이상**이 **5분 안에** 반전 규칙을 자기 말로 설명하고 첫 두 퍼즐을 외부 도움 없이 해결, **5명 이상**이 **15분 후** 추가 퍼즐을 자발적으로 선택, 미리보기 오해 **2명 이하**. 모집·실행은 사람이 수행하며 미모집·관찰 누락은 미검증이다. 8명은 시장 대표 표본이 아니며 기준 통과도 판매 가능 인증이 아니다. 유도 도움, 막힘·중도 종료·오해, 재도전 이유, 이미지·소리 만족과 기억한 차별점을 정성 기록하고 개인정보를 저장하지 않는다.

## 7. 기존 프로토타입에서 시작할 7일 실험 제안

실험 시작 시점·실제 가용 시간·모집 가능 인원은 아직 기록되지 않았다. 아래는 향후 task의 작업 순서이며 이번 문서 작성이 실험 1일차 완료를 뜻하지 않는다.

| 구간 | 제한된 작업과 종료 시 확인할 증거 |
| --- | --- |
| 1일 | 기존 두 퍼즐/조작 기준선, 준비된 엔진과 실행 로그, 포커스 QA 전제, 가용 시간·사람 관찰 일정 확인. |
| 2–4일 | MECH-001에서 여섯 퍼즐과 해답·최소 수·undo/회전 검사, 제작 시간 기록. PRODUCT-001의 시청각/권리 명세와 실제 파일을 구분. |
| 5일 | MEDIA-001의 작은 시청각 실물과 설정·권리 기록, SLICE-001의 학습→응용→완료 흐름 통합. 새 규칙·제품 규모 확대는 자동 승인하지 않는다. |
| 6일 | 기존 보호 검사·독립 QA·추가 검사 각각 실제 실행, 화면·청취·저장/입력 확인. export 도구가 없으면 Windows 빌드는 미검증으로 남긴다. |
| 7일 | 준비된 여섯 퍼즐로 사람의 실제 관찰과 종료 평가. MARKET-001의 근거 보강과 함께 DECIDE-001에서 GO/REVISE/STOP 조건 검토. |

GO는 기술·사람·콘텐츠·품질·권리 증거가 충족된 경우에도 후속 검토 제안일 뿐이다. REVISE는 기준을 유지하는 제한된 수정 실험, STOP은 핵심 선택/만족 가설 실패나 범위 확대 없이는 성립하지 않는 경우의 중단 제안이다. 누락된 자료는 보류로 명시한다. 어떤 경우도 최종 게임·지출·외부 공개·Steam 출시 승인이 자동 발생하지 않으며 최종 결정은 **PENDING_HUMAN_APPROVAL**로 남긴다.

## 8. PLAN-001과 변경 범위 보존

PLAN-001은 backlog에 존재하지만 task 정의 파일은 실제 실행 상태를 보장하지 않는다. review 상태일 가능성을 유지하며 승인·병합·삭제하지 않았다. 이전 콘셉트 본문을 감사/선정 입력으로 사용하지 않았고 현재 최종 게임 선정의 근거로 승격하지 않는다. 기존 작업공간에는 감사 전부터 다수 변경 파일이 있었으므로 이를 이번 작업의 수정으로 주장하지 않는다. Git 커밋·브랜치 push·의존성 설치·구매·외부 연락·게시를 수행하지 않았다.

## 9. 이번 감사에서 실제 수행한 검증

로컬 파일 목록·코드·테스트·위 문서를 읽고 JSON을 Python 표준 라이브러리로 파싱했다. 현재 퍼즐 두 개, 도장 두 종, 입력/진행 경계, QA 실행 대상과 선택 테스트의 차이를 정적으로 대조했다. PATH 엔진 탐색과 환경/작업공간 설정 파일 존재 확인을 수행했다. 작성 후 UTF-8·필수 항목·상대 문서 링크 존재·기존 JSON 상태/링크 수·소스 보호 및 허용 경로 밖 파일의 SHA-256 보존을 검사했다.

이는 문서 정합성·변경 범위 검사다. Godot 테스트·전체 하네스 테스트·Windows 빌드·성능 측정·스크린샷 관찰·오디오 청취·신규 모집/플레이테스트·라이선스 공식 조건 재조사·웹/시장 자료 갱신은 수행하지 않았다. 기존 정적 검사 횟수를 이번 자동 실행 결과로 재사용하지 않는다.
