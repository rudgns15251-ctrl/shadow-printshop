## 변경 범위와 실행

기존 game_state.gd, main.gd, main.tscn, project.godot, 기존 테스트·문서를 수정하지 않았다. 최초 두 퍼즐의 제목·시작·목표·해답을 그대로 유지했다. 기존 기본 실행은 계속 두 퍼즐이며, 6퍼즐은 별도 실험 장면이다.

- scripts/mech_state.gd: 기존 모델 상속. XOR, 회전, 미리보기, 인쇄 이력, 취소, 완료 후 인쇄 거부, 수동 다음 진행을 유지한다. 데이터 접근·초기화·도장 허용 여부만 확장한다.
- scripts/mech_main.gd 및 mech_main.tscn: 기존 화면/조작 상속, 보드별 금지 도장 버튼 비활성화 및 6퍼즐 종료 문구.
- data/mech_puzzles.json 및 data/mech_data.gd: 같은 데이터의 JSON/GDScript 표현. 오프라인 검증은 두 표현의 일치를 검사한다.
- tests/mech_cases.gd: SceneTree 추가 테스트. 현재 독립 QA의 자동 실행 대상이 아니다. 오류 누적 후 quit(1), 성공시 quit(0).
- tests/mech_offline.py: 표준 라이브러리만 사용하는 별도 데이터 검사. GDScript 실행을 대신하지 않는다.

저장소 루트에서 실행할 명령:


Godot 명령 두 개는 실행 예시이며 **미실행**. PATH의 godot/godot4/godot-mono 조회에서 실행 파일을 찾지 못했다. 추가 설치·다운로드·네트워크·Git 접근은 하지 않았다. 기존 회귀 테스트도 이번 작업에서는 미실행이다.

## 데이터와 해답

칸은 행 우선 3×3, 회전은 시계 방향이다. A=ㄱ 세 칸, B=가장자리 막대 세 칸. 데이터 solution의 정수는 `도장 인덱스×4 + 회전 횟수`이다. 모든 보드는 고정 정렬, 이동 없음. 인쇄/회전 횟수 제한 없음(null), 중간 도안 제한 없음, 필수 입력 순서 없음(false). 선택·회전·미리보기는 무료이며 인쇄만 카운트한다. 3·4번의 B 전용은 별도 실험 조건이며 기존 두 퍼즐에 적용하지 않는다.

| 보드 | 용도 | 사용 도장 | 검증 해답 | 실제 BFS 최소 인쇄 | 도달 상태 수 |
| --- | --- | --- | --- | --- | --- |
| 01 | 기존 회전 학습 유지 | A/B | A0 → A90 | 2 | 256 |
| 02 | 기존 잉크 제거 응용 유지 | A/B | A180 → B90 | 2 | 256 |
| 03 | 단일 가장자리 학습 | B | B0 | 1 | 16 |
| 04 | 가장자리 겹침 상쇄 응용 | B | B0 → B90 → B180 | 3 | 16 |
| 05 | 잉크가 있는 시작에서 혼합 응용 | A/B | A0 → A180 → B0 | 3 | 256 |
| 06 | 네 인쇄 합성 응용 | A/B | A0 → A90 → A180 → B0 | 4 | 256 |

각 항목은 도장을 선택하고 해당 각도로 회전한 다음 PRINT한다. 실제 키 입력으로는 01은 `1 Space E Space`, 02는 `E E Space 2 Q Space`, 03은 `Space`(B/0 초기), 04는 `Space E Space E Space`, 05는 `1 Space E E Space 2 Q Q Space`, 06은 `1 Space E Space E Space 2 Q Q Space`이다. 초기화 직후를 전제로 하며 도장 변경은 회전을 유지한다. JSON의 시작/목표가 도안의 정본이다.

## 실제 측정과 한계

실제 실행: `python3 projects/first-game/game/tests/mech_offline.py`, 종료 코드 0. 각 보드에서 허용된 모든 방향의 도장을 간선으로 BFS 큐가 소진될 때까지 탐색했다. 총 1,056개 도달 상태(256×4+16×2)를 방문했고 위 최소 인쇄 수와 데이터 인증값이 일치했다. 동일 인쇄 비용의 고정 소형 보드에 한정한 수학적 최소치이며, 사람의 풀이 시간/인지 난도 인증이 아니다. 지정 해답은 목표에 조기 도달하지 않고 마지막 인쇄에서 완료한다.

보드별 서로 다른 길이 12 입력열 1,000개(총 6,000개)를 Python 참조로 적용하고 완료 후 인쇄 거부를 모사한 뒤 이력을 역순 복원하여 시작 보드 복원을 확인했다. JSON/GDScript 데이터 일치와 최초 두 보드의 시작/목표도 확인했다. **Python 검사는 실제 Godot undo 구현·선택/회전 복원을 실행한 결과가 아니다.**

SceneTree 테스트에는 실제 모델의 정답/오답, 완료 인쇄 거부, 금지 도장, 양방향 4회 회전, 수동 진행, 마지막 경계, BFS 값 일치와 보드별 1,000개 입력열을 포함했다. 각 undo에서 인쇄 직전 전체 snapshot(보드·횟수·이력·선택·회전)을 비교하고, 마지막에 초기 snapshot 및 빈 undo를 검사한다. 현재 **미실행**이므로 테스트 통과·구문 유효성을 주장하지 않는다.

## 다양성 실험의 해석과 승인 경계

6개는 콘텐츠 수 목표이며 여섯 종류의 근본 규칙은 아니다. 추가 보드는 도장 제한, 인쇄 조합 수, 시작 잉크로 학습/응용 조건을 바꾼다. 특히 03·04는 같은 B 가장자리 구조를 재사용한다. 고정 중심 칸은 어느 도장으로도 바뀌지 않으며, 시작과 목표의 동일 잉크를 함께 바꾸는 것은 필요한 XOR 차이를 바꾸지 않아 표면적 변형일 뿐이다. 회전만 다른 보드도 새로운 메커니즘으로 세지 않는다. 05·06의 시작 무늬는 표시/인지 조건이고 그 자체가 새로운 규칙은 아니다.

고정 XOR는 교환법칙 때문에 모든 해답 인쇄의 순서 교환이 최종 보드를 유지한다. 같은 도장을 같은 방향으로 두 번 찍으면 상쇄된다. 완료 뒤 인쇄 거부 때문에 목표에 조기 도달하는 긴 입력열은 남은 인쇄를 실행할 수 없으나, 이것을 순서 전략성이라고 주장하지 않는다. 순서 잠금, 이동 가능한 도장, 중간 상태 제약, 소비형 잉크 등 근본 규칙 변경은 구현하지 않았으며 **별도 승인 필요**다. B 전용 조건의 재미·학습 효과와 6퍼즐의 실제 난도 순서는 사람 관찰로 검증해야 한다. 독립 QA와 사람의 최종 승인 상태는 변경하지 않는다.
