# PROTO-002 회귀 검증 기록

작성일: 2026-10-12. 대상: 기존 C01 Godot 기술 프로토타입의 상태 규칙.
이번 변경은 tests/regression_test.gd와 이 문서뿐이다. 게임 규칙, 화면, 조작, 퍼즐 데이터는 수정하지 않았다. tests/smoke_test.gd와 docs/VALIDATION.json은 보호 파일이며 내용이 그대로임을 SHA-256 비교로 확인했다.

## 테스트 구성과 판정

regression_test.gd는 SceneTree를 확장하고 실제 scripts/game_state.gd의 State.new()를 사용한다. 모의 상태나 비공개 필드 변경을 사용하지 않는다. 기대값은 테스트에 고정한 3×3 배열과 상태 사전으로 구성하며, 구현의 MASKS/PUZZLES 상수나 preview() 결과로 정답을 만들지 않는다. 조합 검사의 참조 계산은 고정 마스크의 1인 셀에만 1 - 기존 값으로 토글한다.

항상 실행되는 _expect 비교를 사용한다. Godot의 내장 assert가 생략될 수 있는 빌드에서도 비교를 생략하지 않는다. 기대값 불일치는 실패 수와 세부 메시지를 기록하며 quit(1)로 끝낸다. 시나리오 5그룹과 조합 1,024개가 끝났는지도 검사한다. 모든 비교가 끝나고 실패가 0일 때만 성공 표식 HARNESS_REGRESSION_PASS를 출력하고 quit(0)로 종료한다. 엔진의 파싱/실행 오류가 있거나 표식이 없으면 성공으로 판단하면 안 된다.

## 정확한 자동 검사 범위

| 시나리오 | 검사 내용 |
| --- | --- |
| 초기 상태와 선택 | 퍼즐 수 2, 첫 퍼즐 시작 보드·목표·제목, A/0도, 인쇄 횟수와 기록 0. A/B 선택 성공, 선택 변경 시 기존 회전 유지. 인덱스 -1, 2, 99 거부 및 전체 상태 불변. |
| 회전 | A/B 각각 시계 방향 4회와 반시계 방향 4회의 중간 마스크 및 원위치. 직접 지정 -9, -5, -4, -1, 0, 1, 3, 4, 5, 9의 정규화. 보드·목표·인쇄 횟수·기록은 변하지 않음. |
| 미리보기·XOR·인쇄 | 두 퍼즐에서 B/90도 인쇄 전 고정 배열 비교, 반복 미리보기의 무변경, 인쇄 후 셀·횟수·기록 검증. 같은 스탬프를 두 번 인쇄하면 시작 보드로 돌아오지만 횟수/기록은 2. 두 번째 퍼즐에서는 기존 잉크가 지워지는 셀도 검사. |
| undo·reset | 빈 기록 undo 및 미완성 상태의 다음 퍼즐 요청 거부. 인쇄 뒤 선택/회전을 바꾸고 undo하면 인쇄 직전 보드·선택·회전·횟수·기록 복원. 두 단계 undo, 기록 소진 후 거부, undo 후 새 인쇄 기록, 인쇄 후 reset의 기본 선택·회전·시작 보드 복원과 기록 제거, 반복 reset. 두 퍼즐에서 각각 검사. |

| 첫 퍼즐 목표 | A/0도 인쇄 → 오른쪽 회전 → A/90도 인쇄. 목표 도달, 횟수/기록 2, 미리보기 고정, 추가 인쇄 거부, undo로 목표 해제 및 이동 차단, 재해결, 해결 상태 reset, 다시 해결 후 다음 퍼즐 이동. |
| 두 번째 퍼즐과 끝 경계 | 이동 시 두 번째 시작 보드, A/0도, 횟수/기록 0; 이전 퍼즐로 undo 불가. A/180도 인쇄 → B 선택 → 왼쪽 회전 → B/90도 인쇄로 목표 도달. 미리보기만으로는 해결되지 않음. 해결 후 추가 인쇄 및 세 번째 퍼즐/처음으로 순환 거부. undo·재해결·reset 가능하며 reset은 두 번째 퍼즐에 머묾. |
| 제한된 조합 회귀 | 두 퍼즐 각각 A/B × 0/90/180/270도 = 8종의 순서 있는 3회 인쇄 조합 512개, 총 1,024개. 조합마다 3번 인쇄 요청(총 3,072번), 선택/회전, 참조 미리보기, 미리보기 무변경, 인쇄 반환값과 전체 상태 검증. 중간에 해결되면 나머지 인쇄 요청은 거부되어야 함. 수락된 기록을 역순으로 모두 undo하여 스냅샷 복원, 빈 undo 무변경, reset 검사. |

전체 상태 비교에는 퍼즐 인덱스·제목·보드·목표·선택·회전·인쇄 횟수·기록 크기·해결 여부가 포함된다. get_mask, mismatch_count, can_advance 등 공개 조회 결과도 별도로 검사한다. 이 조합 검사는 길이 3의 인쇄 경로를 대상으로 하며 모든 길이의 행동 순서를 전수 검사한다는 뜻은 아니다.

## 이번에 실제 수행한 검증

- Node로 정적 소스 검사 10항목 통과: SceneTree 진입점, 성공 표식 단일 위치, 실패 분기 선행, 명시적 오류 종료와 return, 그룹/조합 완료 가드, 구현 상수/비공개 상태를 정답에 사용하지 않음, OS·외부 파일·네트워크 API 없음, preload 대상 존재, 보호 파일 2개의 바이트 보존.
- Node로 기대 데이터 검사 16항목 통과: 기존 퍼즐 배열과 일치, 두 마스크의 8개 회전 배열, 각 마스크의 한 바퀴 복귀, 두 퍼즐의 2회 인쇄 해답, 두 번째 퍼즐 중간 배열, 각 퍼즐 B/90도 첫 인쇄 고정 배열. 이는 소스 데이터의 계산 검증이며 실제 game_state 실행이 아니다.
- Godot 탐색: godot, godot4, godot.exe, Godot.exe --version 모두 ENOENT. GODOT_BIN은 비어 있고 이 작업공간의 .data/godot_path.txt 및 엔진 실행 파일은 없음.
- godot --headless --path <game> --script res://tests/regression_test.gd 및 기존 smoke_test.gd 실행을 시도했으나 모두 ENOENT로 프로세스를 시작하지 못했다. GDScript 파싱, 회귀 테스트, 스모크 테스트의 런타임 통과 여부는 미검증이다. 성공 표식의 실행 출력은 없었다.
- 독립 qa/scene_probe.gd는 하네스가 자체적으로 준비·실행한다. 이번 작업에서는 수정·실행하지 않았으며 결과를 주장하지 않는다.

엔진 부재를 게임 결함으로 간주하지 않았다. 독립적으로 관찰된 게임 결함과 실행 테스트 실패가 없으므로 구현 수리는 수행하지 않았다. 작업 manifest의 자동 수리 한도는 2회이며, 이후 실제 실패가 관찰되면 허용 범위의 구현만 수정하고 동일 검사를 재실행해야 한다. 테스트 기대값이나 승인 기준을 낮추지 않는다.

## 엔진이 준비된 환경의 실행 방법

아래 명령은 저장소 루트의 PowerShell에서 실행한다. $GodotExe에 이미 설치된 Godot 4 실행 파일의 실제 경로를 넣는다. 설치·다운로드·전역 설정 변경은 이번 작업에서 하지 않았다.

~~~powershell
$GodotExe = '<설치된 Godot 4 실행 파일의 전체 경로>'
$GamePath = Join-Path (Get-Location) 'projects/first-game/game'
& $GodotExe --headless --path $GamePath --script res://tests/regression_test.gd
$LASTEXITCODE
& $GodotExe --headless --path $GamePath --script res://tests/smoke_test.gd
$LASTEXITCODE
~~~

회귀 통과 조건은 종료 코드 0, 성공 표식, 실패/파싱/스크립트 오류 없음이 모두 충족되는 것이다. 기존 스모크와 하네스의 독립 scene probe도 별도로 통과해야 한다. 이 문서는 아직 수행하지 못한 엔진 실행을 통과 기록으로 대체하지 않는다.

## 자동 검사가 대체할 수 없는 수동 UI 확인

사용자는 이번 작업 전에 스탬프 선택, 회전, 인쇄, undo, reset, 퍼즐 해결, 다음 퍼즐 이동이 작동한다고 직접 알려주었다. 이는 사용자 보고이며 이번 에이전트가 새로 수동 플레이한 결과가 아니다. 이번 작업에서는 화면을 직접 조작하거나 새 플레이테스트를 수행하지 않았다.

UI 재검증 시 다음 항목을 실제 창에서 확인한다.

1. 마우스로 A/B 선택과 양방향 회전을 눌러 선택 표시, 회전 각도, 선택 스탬프와 AFTER 미리보기가 일치하는지 확인한다. CURRENT/TARGET은 인쇄 전 변하지 않아야 한다.
2. 키보드 1/2, Q/E, Space/Enter, U/Z, R, N과 같은 기능의 마우스 버튼을 각각 확인한다. 키를 길게 눌렀을 때 자동 반복이 중복 인쇄를 만들지 않는지 확인한다.
3. 첫 퍼즐에서 R → 1 → Space → E → Enter로 해결하고 인쇄 비활성화, MATCH 안내, 다음 퍼즐 활성화를 확인한다. undo로 해결 표시가 해제되고 next가 비활성화되는지도 확인한다.
4. 첫 퍼즐을 다시 해결하고 N으로 이동한 뒤 E → E → Space → 2 → Q → Space로 두 번째 퍼즐을 해결한다. 잉크가 사라지는 셀, 완료 안내, 마지막 next 비활성화, undo/reset으로 재시도 가능 여부를 확인한다.
5. 창 크기 변경 시 보드·텍스트·버튼이 잘리지 않고 구분되는지, 마우스 클릭 영역과 키보드 입력 반응이 일치하는지 확인한다.

회귀 테스트는 상태 API만 호출하므로 버튼 연결, 실제 입력 전달, 포커스/키 반복, 화면 배치·색·글자 가독성, 창 크기/DPI 및 렌더링 문제를 확인하지 않는다. 기존 스모크와 scene probe에도 실제 사람의 UI 확인은 필요하다. 길이 3을 초과하는 모든 혼합 행동 순서, 모든 정수 범위의 회전 입력, 다른 엔진 버전·내보낸 Windows 빌드·장시간 실행은 이번 검증 범위 밖이다. 재미·난이도·접근성·시장성·판매량에 관한 검증이나 주장은 없다.
