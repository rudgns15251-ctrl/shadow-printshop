# PROTO-001 — 음영 인쇄소 기술 프로토타입

작성일: 2026-10-12. 상태: 구현 파일 작성 및 정적·퍼즐 데이터 검사 완료. **Godot 실행 검증, 화면 확인, 사람 플레이테스트, 독립 검증은 미실시**이다. 실행 가능한 Godot 4.x를 이 작업 환경에서 찾지 못했다. 릴리스 게임·최종 콘셉트 승인·상품성 검증 결과가 아니다.

## 범위와 출처

사용한 게임 설계는 [independent_concepts.md의 C01](../../design/independent_concepts.md)과 [market_assessment.md의 C01 평가](../../research/market_assessment.md)이다. 다른 프로젝트나 개인 맥락은 사용하지 않았다. 핵심 루프는 목표 확인 → 판 선택·회전 → 반전 미리보기 → 인쇄 → 취소·재도전이다.

이번 과제의 경계는 **3×3 보드, 판 2개, 수작업 퍼즐 2개**이다. 원문의 6개 프로토타입 퍼즐 계획, 24/36개 제품 범위, 사람 관찰 기준을 달성했다고 주장하지 않는다. 기존 승인 조건과 테스트 규칙은 변경하지 않았다.

- 모든 칸은 0(밝은 종이) 또는 1(어두운 잉크)이다.
- 판에서 1인 칸만 XOR 반전한다. 0 XOR 1 = 1, 1 XOR 1 = 0이다.
- A는 ㄱ 모양 세 칸, B는 가장자리 가로 세 칸이다. 판은 보드 전체에 고정 정렬하며 이동·드래그·칸 직접 편집은 없다.
- 회전은 보드 중심을 기준으로 시계 방향 0/90/180/270도이다. Q는 반시계, E는 시계 방향 90도씩 변경한다.
- 판을 바꿔도 현재 회전은 유지된다. 초기화와 다음 퍼즐은 A/0도로 시작한다.
- 판 선택, 회전, 미리보기는 턴을 소비하지 않는다. 인쇄만 횟수와 취소 이력을 증가시킨다.
- 취소는 마지막 인쇄 직전의 보드·인쇄 횟수·선택 판·회전을 복원한다. 이후에 선택만 바꿨더라도 복원 기준은 인쇄 직전이다.
- 초기화는 현재 퍼즐의 시작 도안과 기본 선택을 복원하고 취소 이력을 비운다.
- 보드가 목표와 정확히 같아야 완료된다. 완료 뒤 추가 인쇄는 거부되며 미리보기는 완료 보드를 보여 준다. 취소와 초기화는 가능하다.
- 첫 퍼즐 완료 뒤에만 다음 퍼즐로 갈 수 있다. 진행은 자동이 아니다. 퍼즐 사이의 취소는 불가능하다.
- 두 번째 완료가 종료 지점이다. 더 많은 퍼즐이나 자동 반복은 없다. 처음부터 재실행하려면 창을 닫고 다시 실행한다.

고정 XOR 마스크의 순서는 최종 보드에 영향을 주지 않고, 같은 방향의 같은 판을 두 번 인쇄하면 상쇄된다. 중간 상태에 별도 제약은 없다. 이 성질을 의도적으로 유지하여 평가 문서의 반증 질문을 검토할 수 있게 했다. 순서 선택의 전략성·독창성·구매 가치를 주장하지 않는다.

모델은 UI 노드, 시간, 무작위 입력, 저장 파일에 의존하지 않는다. 반환하는 보드·목표·판·스냅샷은 복사본이다. 게임 코드는 외부 파일 읽기/쓰기, 네트워크, 프로세스 실행, 셸, 파일 삭제, 플러그인, DLL/GDExtension을 사용하지 않는다. res:// 참조는 프로젝트 내부의 장면·스크립트만 로드한다. Godot 자체가 생성할 수 있는 프로젝트 캐시는 게임의 저장 기능과 별개이다. 외부 자산·폰트·라이브러리는 다운로드하거나 설치하지 않았다.

## 사람이 실행하는 방법

이미 보유한 Godot 4.x **일반 에디터**에서 이 폴더의 project.godot를 가져오고 F6 대신 **F5(프로젝트 실행)**를 누른다. 별도 빌드, .NET, 플러그인 또는 자산은 필요하지 않도록 구성했다. 실제 Godot 버전 호환성은 아직 실행 확인하지 않았다.

창 설정은 1120×840이고 최소 창 크기는 1040×840이다. 세 보드와 하단 조작 안내가 모두 보이는지 확인한다. 작은 화면·고배율 환경에서의 배치는 미검증이다. 화면 텍스트는 기본 폰트의 영문·숫자를 사용하며 아래 표가 한국어 안내이다.

| 화면/입력 | 의미 |
| --- | --- |
| CURRENT / before | 지금까지 인쇄한 현재 도안 |
| AFTER / preview | 지금 선택한 판을 한 번 인쇄한 예상 도안 |
| TARGET / order | 만들어야 하는 목표 도안 |
| SELECTED STAMP | 회전된 현재 판. 1인 칸이 반전 영역 |
| 주황 테두리 | 현재/미리보기 보드에서 반전될 칸 |
| Prints | 현재 풀이의 인쇄 횟수 |
| Different cells | 현재 보드와 목표가 다른 칸 수 |
| 1 / 2 | A / B 판 선택 |
| Q / E | 왼쪽 / 오른쪽으로 90도 회전 |
| Space / Enter | 한 번 인쇄 |
| U / Z | 마지막 인쇄 취소 |
| R | 현재 퍼즐 초기화 |
| N | 완료된 첫 퍼즐에서 두 번째로 진행 |

마우스는 같은 이름의 버튼을 클릭한다. 보드 클릭·호버로 상태가 바뀌지 않는다. 키를 계속 누른 반복 입력은 무시한다. 창 닫기로 종료한다. 완료되면 인쇄 버튼은 비활성화된다. 첫 완료에서만 다음 버튼이 활성화된다. 빈 이력에서는 취소 버튼이 비활성화된다. 색 외에도 모든 칸에 0/1 숫자가 있어 명암과 반전 내용을 읽을 수 있다.

## 재현 시나리오와 기대 결과

아래 칸 표기는 위에서 아래로 행을 읽으며, 왼쪽부터 오른쪽으로 열을 읽는다.

### 1. 미리보기와 첫 퍼즐 완료

새 실행 또는 첫 퍼즐에서 R을 누른다. A/0도, 인쇄 0회, 현재 000 / 000 / 000이다.

입력: **1 → Space → E → Space**

1. 첫 인쇄 전 미리보기는 110 / 100 / 000이다.
2. 첫 Space 후 현재가 그 미리보기와 같고 인쇄는 1회다.
3. E 후 회전은 90도, 현재는 그대로이며 미리보기는 101 / 101 / 000이다.
4. 두 번째 Space 후 목표와 일치하고 인쇄는 2회다. 다음 버튼이 활성화된다.
5. Space를 더 눌러도 보드·횟수가 바뀌지 않는다.
6. U를 누르면 첫 인쇄 후 도안으로 돌아가고 회전은 90도, 횟수는 1회다. 다음 버튼이 비활성화된다.
7. Space를 다시 누르면 완료된다. N으로 두 번째 퍼즐로 진행한다.

마우스 대응: A → PRINT → rotate right → PRINT → next puzzle.

### 2. 두 번째 퍼즐과 마지막 경계

N 직후 시작은 010 / 100 / 001, 목표는 011 / 100 / 011이다. A/0도, 인쇄 0회이다.

입력: **E → E → Space → 2 → Q → Space**

1. A/180도 인쇄 후 현재는 010 / 101 / 010, 인쇄 1회다.
2. B 선택은 180도를 유지하며 Q로 90도가 된다.
3. 미리보기는 011 / 100 / 011이다. 일부 칸의 잉크가 제거되는 것도 확인한다.
4. 마지막 Space 후 인쇄 2회, 목표 일치, 종료 메시지가 나온다. 다음 버튼은 비활성화된다.
5. N을 눌러도 진행하지 않는다.
6. R을 누르면 두 번째 시작 도안, A/0도, 인쇄 0회로 복원된다. 첫 퍼즐로 되돌아가지는 않는다.

마우스 대응: rotate right 두 번 → PRINT → B → rotate left → PRINT.

### 3. XOR 상쇄, 취소, 초기화

첫 퍼즐 새 실행에서 입력: **R → 1 → Space → Space → U → U → U**

같은 A/0도 두 번 인쇄하면 빈 시작 도안으로 돌아오지만 횟수는 2회이다. 두 번 취소하면 빈 보드·횟수 0·빈 이력이 된다. 세 번째 취소는 변화가 없어야 한다.

추가 입력: **2 → E → Space → R**

첫 퍼즐의 빈 보드·A/0도·인쇄 0회로 복원되어야 한다. 취소로 초기화 이전 인쇄를 복원할 수 없어야 한다.

### 4. 회전과 입력 일관성

초기화 후 E를 네 번 누르면 판이 처음 방향으로 돌아와야 한다. Q 한 번은 270도여야 한다. Space를 누르기 전까지 현재 보드와 횟수는 바뀌지 않아야 한다. 마우스로 같은 회전·판·인쇄를 선택해도 동일한 결과여야 한다. 실제 키보드 포커스, 키를 길게 누르는 동작, 창 크기와 글자 잘림은 사람이 확인해야 한다.

## 자동 회귀 테스트 실행

설치된 Godot 실행 파일을 사용해 **game 폴더에서** 다음을 실행한다. godot가 PATH에 없다면 본인이 보유한 실행 파일의 경로로 대체한다. 아래는 사용자가 수행할 검증 명령이며 게임 스크립트가 셸을 실행하지 않는다.

```text
godot --headless --path . --import
godot --headless --path . --script res://tests/smoke_test.gd
godot --headless --path . --quit-after 5
```

smoke_test.gd는 SceneTree를 확장하며 초기 전이, 명시적인 여덟 회전 마스크, 회전 순환·음수, 미리보기 순수성·복사본, 인쇄/취소/초기화, 완료 잠금, 진행 경계, XOR 상쇄·교환성, 두 퍼즐 해답을 검사하도록 작성했다. 1,000개 고정 시드 입력열(각 최대 12인쇄)에 대해 복제 상태의 결정론적 재생, 이진 불변식, 미리보기 일치, 역순 취소를 검사한다. 동일 테스트 안에서 장면을 생성하고 키 입력 핸들러·버튼 신호·보드 바인딩도 검사한다. 버튼 신호 호출은 실제 마우스 위치·운영체제 입력 검증을 대체하지 않는다.

실패를 누적하고 실패가 하나라도 있으면 quit(1)로 종료한다. 모든 검사가 끝나 통과한 경우에만 HARNESS_SMOKE_PASS를 출력하고 quit(0)을 호출한다. 종료 코드 0, 성공 마커, 오류 로그 없음이 함께 필요하다. 파싱 오류·멈춤·시간 초과도 통과가 아니다. 최대 90초 안에 끝나지 않으면 실패로 기록한다.

**이 테스트는 Codex가 작성했으며 아직 실행하지 않았다. 독립 검증이 아니다.** 별도 검토자가 실제 Godot에서 파싱·실행하고 테스트의 누락과 오류도 검토해야 한다.

## 실제 수행한 검증과 한계

[VALIDATION.json](VALIDATION.json)에 이번 작업의 결과를 기록했다.

- Node 로컬 파일 도구로 필수 구현 파일, 프로젝트 내부 res:// 참조, 일반 파일 여부, 금지 API·외부 참조 패턴을 검사했다. 49개 정적·데이터 검사 항목이 통과했다. 이는 보안 샌드박스 인증이나 GDScript 파싱 검사가 아니다.
- game_state.gd의 판·시작·목표 배열을 추출하여 별도 Node 계산으로 각 퍼즐의 도달 가능한 256개 보드 상태를 전수 탐색했다. 두 퍼즐 모두 최단 인쇄 수 2이며 위 두 입력열의 판/방향 조합이 목표에 도달함을 확인했다. **Godot 상태 모델을 실행한 결과가 아니라 데이터와 수학 규칙에 대한 오프라인 확인**이다.
- godot와 godot4의 --version 실행은 모두 ENOENT로 실패했다. PATH의 대체 실행 파일 이름, 이 작업공간 안의 실행 파일·엔진 설정, GODOT_BIN 설정에서도 사용할 엔진을 찾지 못했다. 외부 폴더를 검색하거나 설치·다운로드·권한 확대는 하지 않았다.
- Godot import, smoke_test.gd 실행, headless 시작 장면 실행, 실제 화면 렌더링은 **미실시**이다. 성공 마커를 실제 출력했다고 주장하지 않는다.
- 사람 플레이테스트, 신규 시장 조사, 판매 분석, 상품성 판단, 독립 기술 검증은 **미실시**이다. 평가 문서의 insufficient_evidence 상태를 바꾸지 않는다.

저장·최고 기록·힌트·오디오·애니메이션·퍼즐 생성·설정·패드·Steam 연동·배포 빌드는 없다. 인쇄 횟수 표시로 재도전할 수 있지만 최고 기록을 저장하지 않는다. 중간 제약 없는 XOR여서 인쇄 순서가 바뀌어도 최종 도안은 같다. 이 작은 실험이 재미, 난이도 곡선, 차별성 또는 유료 제품으로서의 분량을 입증하지 않는다.

## 독립 리뷰와 사람 확인

검토자는 먼저 위 엔진 검사를 실행하고 원본 로그와 사용 Godot 버전을 작업공간 안의 game/docs/에 기록할 수 있다. 그다음 두 퍼즐을 실제 창에서 마우스·키보드로 풀고, 미리보기와 실제 인쇄 일치, 취소/초기화 경계, 화면 가독성, 두 번째 완료 이후 동작을 확인한다.

처음 접하는 사람에게는 해답 입력열을 먼저 보여 주지 않고 화면 안내만으로 반전 규칙과 회전이 이해되는지 관찰할 수 있다. 막힘·오해·도움 요청·중도 종료·자발적 재도전 여부를 사실대로 기록한다. 기존 기획의 인원·시간 통과 기준을 이번 두 퍼즐로 충족했다고 간주하지 않는다. 실제 사람 리뷰 결과를 생성 테스트 결과로 대신하지 않는다. 개인정보를 저장소에 기록하지 않는다.

최종 콘셉트 선택, 추가 제작, 구매, 공개 배포, 출시 승인은 사용자에게 있다. 이 작업은 그 승인을 요청하거나 대신하지 않는다.
