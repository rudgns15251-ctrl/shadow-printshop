# ITER-002 — 인쇄 버튼 포커스 입력 QA

이 프로젝트는 실험용 테스트 게임이다. 상업 콘셉트 승인, 사람 플레이테스트, 시장 검증 결과를 의미하지 않는다.

## 변경 범위와 전후 동작

이번 개선은 qa_case 추가다. 기존 게임 동작을 변경하지 않는다. 이전에는 이번 작업의 독립적인 포커스 입력 체크리스트와 관찰 도구가 없었고, 이후에는 이 문서와 선택 실행용 `docs/iter_002_focus_observer.gd`로 물리 키 누름/반복/해제 및 버튼 활성화 횟수를 구분해 관찰할 수 있다. 기존 문서를 읽지 못했으므로 기존 QA에 동일 사례가 없었다고 단정하지 않는다.

`smoke_test.gd`, `regression_test.gd`, `VALIDATION.json`, 기존 사람 테스트 기록, 게임 코드, 퍼즐, 조작, 상태 의미, QA 게이트 및 하네스는 이번 작업에서 수정하지 않았다. 파일 비교 검증은 실행하지 못했다.

## 실제 게임에서 수행할 시나리오

각 사례를 첫 퍼즐 초기화 직후부터 독립적으로 시작한다. 시작 보드를 전체 캡처하고 인쇄 횟수 0, 취소 이력 길이 0을 확인한다. Tab 또는 기존 UI 탐색 방식으로 **인쇄 버튼의 실제 포커스**를 확인한다. 마우스로 인쇄 버튼을 누르는 것을 초기 조건에 포함하지 않는다. 이력은 기존 디버거/상태 관찰 수단으로 확인하며, 이력 확인 없이 화면 카운터만으로 통과 판정하지 않는다.

| 사례 | 입력 | 확인해야 할 결과 |
| --- | --- | --- |
| F01 | Space 한 번 누르고 놓기 | 누름부터 해제 후까지 실제 인쇄 증가량 1, 취소 이력 증가량 1. 버튼과 전역 단축키의 중복 처리 없음. |
| F02 | 새 초기 조건에서 Enter 한 번 누르고 놓기 | 실제 인쇄 증가량 1, 취소 이력 증가량 1. 버튼과 전역 단축키의 중복 처리 없음. |
| F03 | 새 초기 조건에서 Space를 2초간 계속 누른 뒤 놓기 | OS 반복 이벤트가 있어도 전체 인쇄 증가량 1, 이력 증가량 1. 해제 후 기존 취소 조작 한 번으로 시작 보드 전체, 인쇄 0, 빈 이력 복원. |
| F04 | 초기화 후 Space 누름·해제, 다시 누름·해제. 두 번째 입력은 게임 상태가 인쇄를 허용할 때 수행 | 두 개의 의도적인 물리 누름을 시간 간격만으로 합치지 않는다. 허용된 각 입력마다 실제 인쇄와 이력이 1 증가. 취소 한 번은 마지막 실제 인쇄 하나만 되돌리고, 다음 취소는 시작 상태 복원. |

F01/F02도 취소 한 번으로 시작 보드, 인쇄 0, 빈 이력이 복원되는지 확인한다. F03에서 반복 이벤트가 관찰되지 않았다면 ‘2초 유지 확인, OS 반복 경로 미확인’으로 기록한다. 두 번의 별도 Space 누름을 ‘2초 이내이므로 한 번’으로 판정하지 않는다. 임의 시간 기반 쿨다운은 요구사항이 아니다.

## 선택 실행용 Godot 관찰 테스트

`docs/iter_002_focus_observer.gd`는 프로젝트의 기존 main_scene을 열고 텍스트에 `인쇄` 또는 `print`가 포함된 Button 하나를 찾아 포커스를 준다. 자동 후보가 없거나 여러 개면 명시적으로 중단한다. 게임 이름/노드 경로를 읽지 못했기 때문에 자동 식별은 미검증이며, 실패 시 기존 게임을 직접 실행해 위 체크리스트를 수행한다.

아래 명령은 **실행 예시이며 이번 작업에서 실행하지 않았다**. 기존 환경의 Godot 4 실행 파일로 game/ 디렉터리에서 GUI 실행한다. headless 실행은 실제 Windows 키 입력 검증을 대신하지 못한다.

```text
godot --path . --script docs/iter_002_focus_observer.gd
```

이 도구는 실제 GUI 이벤트 경로를 사용하고 게임 입력을 소비하거나 PRINT를 직접 호출하지 않는다. 각 Space/Enter 물리 누름 구간의 버튼 `pressed` 신호 수, echo 수, 유지 시간을 출력한다. 해제 직후 한 프레임까지 기다려 신호 수가 정확히 1인지 검사한다. 게임이 버튼 신호를 거치지 않고 전역 처리하는 인쇄는 이 수치에 나타나지 않으므로 **신호 1회만으로 실제 인쇄·이력 검증 통과를 선언하지 않는다**. 포커스 유지, 실제 카운터, 이력, 취소 후 보드는 위 수동 사례로 별도 확인한다. 키를 겹쳐 누르지 않는다. 취소 조작을 위해 포커스를 옮겼다면 다음 인쇄 입력 전에 다시 인쇄 버튼으로 이동한다.

## 실제 수행 및 제한

- 도구 호출: `functions.exec`에서 사용 가능한 도구 메타데이터 확인, `apply_patch`로 이 문서와 선택 관찰 스크립트 추가.
- 셸 명령, 네트워크 접근, Git 명령/커밋, 의존성 설치: 실행하지 않음.
- Godot 구문 검사, 선택 테스트 실행, 기존 smoke/regression 실행, 실제 Windows 입력, 사람 플레이테스트: 실행하지 않음.
- 이유: 셸 명령 사용이 명시적으로 금지되었고, 제공된 도구에 이를 사용하지 않는 로컬 파일 읽기/Godot 실행 기능이 없음. 기존 프로젝트의 API·Godot 버전·노드 구성도 확인하지 못함.
- 현재 판정: **미검증**. 테스트 통과 또는 게임 결함 해결을 주장하지 않음. 런타임 수정 없이 QA 범위만 추가함.
